# Dino Atlas 접근권한·관리자 화면 설계

## 현재 구현

- 일반 사용자는 기본적으로 `free` 권한으로 시작하며, `access-policy.js`에 고정된 대표 생물 30종을 볼 수 있다.
- 무료 사용자가 `전체 도감`을 선택하면 모든 생물의 위치와 이름은 둘러볼 수 있지만, 무료 목록 밖의 상세 정보와 갤러리는 구독 안내 상태로 잠긴다.
- `subscriber` 권한에서는 모든 생물의 상세 정보와 갤러리를 볼 수 있다.
- 검수 상태, 프롬프트, 시드, 생성 워크플로, 내부 판정과 원본 자산 경로는 일반 사용자 화면에 노출하지 않는다.
- 관리자 검수 화면은 로컬 전용 `admin.html`에 모았다. GitHub Pages 배포 산출물에는 이 파일을 포함하지 않는다.
- 데스크톱 계통도의 우측 정보 패널은 기본으로 열리고, 1100px 이하 화면에서는 기본으로 접힌다. 모바일에서 생물을 선택하면 상세 패널이 열린다.

무료 목록은 정보 난이도(`knowledgeLevel`)와 의도적으로 분리한다. 난이도 재분류가 상품 접근권한을 바꾸지 않게 하기 위해서다.

## 권한 연결 계약

배포 환경은 `app.js`를 읽기 전에 서버에서 검증한 권한을 아래처럼 주입할 수 있다.

```html
<script>
  window.DINO_ATLAS_ENTITLEMENT = { catalog: "subscriber" };
</script>
```

허용되는 값은 `free`와 `subscriber`다. 값이 없거나 올바르지 않으면 항상 `free`로 안전하게 되돌아간다.

로컬 개발 환경에서만 다음 미리보기 주소를 쓸 수 있다.

- 무료 사용자: `http://127.0.0.1:8020/`
- 구독 사용자: `http://127.0.0.1:8020/?admin=1&tier=subscriber`
- 관리자 검수: `http://127.0.0.1:8020/admin.html`

`tier` 쿼리는 `localhost` 또는 `127.0.0.1`에서 `admin=1`이 함께 있을 때만 작동한다. 실제 권한 저장 수단으로 사용하지 않는다.

## 상용화 전에 필요한 보안 경계

현재 정적 Pages 구현은 상품 흐름과 화면을 비교하는 UX 프로토타입이다. 브라우저에 내려온 JavaScript와 공개 자산은 사용자가 직접 열어볼 수 있으므로 실제 유료 콘텐츠 보호 수단이 될 수 없다.

구독제를 연결할 때는 다음을 서버 경계로 옮긴다.

1. 로그인과 결제 상태를 서버에서 검증하고, 짧은 수명의 세션으로 권한을 전달한다.
2. 무료 사용자에게는 무료 카탈로그 데이터만 내려주고, 전체 데이터는 인증된 API에서 제공한다.
3. 유료 이미지·영상은 비공개 저장소와 만료되는 서명 URL을 사용한다.
4. 관리자 페이지와 검수 API에는 별도 역할 기반 접근 제어와 감사 기록을 둔다.
5. 관리자용 프롬프트·시드·워크플로·검수 메모를 공개 `app.js`에서 별도 데이터 저장소로 분리한다.

`localStorage`, URL 쿼리, CSS 숨김만으로는 구독 권한을 부여하거나 관리자 정보를 보호하지 않는다.
